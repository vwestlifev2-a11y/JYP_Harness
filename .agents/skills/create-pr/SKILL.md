# Create PR

## 실행 주체

**PR 생성은 반드시 전담 서브 에이전트가 수행한다.** 메인 에이전트는 작업 맥락 전달과 결과 확인을 담당한다. 이미 전담 서브 에이전트로 실행 중이면 아래 생성 절차를 직접 수행하고 다시 위임하지 않는다.

- 메인 에이전트는 `spawn_agent` 또는 환경의 동등한 서브 에이전트 도구로 **한 명**에게 위임한다. 사용자 소유의 새 채팅을 생성하는 도구로 대체하지 않는다.
- 서브 에이전트 도구가 없으면 지원되지 않는다고 알린다. 메인 에이전트가 대신 PR을 생성하지 않는다.
- 스킬 작성·검증만 요청받았다면 실제 브랜치 push나 PR 생성 없이 파일 작업만 한다.

## 인계 준비 — 메인 에이전트

1. 적용되는 `AGENTS.md`를 읽고 실제 작업 저장소 루트를 확인한다. 중첩 저장소를 같은 Git 이력으로 취급하지 않는다.
2. `git status --short`, 브랜치, 원격 URL, HEAD를 확인한다. 미커밋 변경이 대상이라면 프로젝트의 커밋 절차를 먼저 완료한다. PR 생성 요청을 이유로 커밋 승인 규칙을 우회하지 않는다.
3. 사용자 지정 대상 저장소·base·head를 우선한다. 지정이 없으면 원격과 저장소 기본 브랜치에서 식별한다. fork의 head 저장소와 upstream의 base 저장소를 구별한다. 후보가 여러 개라 확정할 수 없으면 해당 정보만 질문한다.
4. 다음 정보를 전담 서브 에이전트에게 전달한다.
   - **역할:** PR 생성 담당 서브 에이전트이며 재위임하지 않는다.
   - **작업 위치:** 절대 경로, 이 `SKILL.md`의 절대 경로, 사용자 요청 원문, 적용 지침.
   - **PR 대상:** GitHub host와 owner/repo, base, head 저장소·브랜치, 로컬 HEAD SHA. 미확정 정보는 미확정으로 표시한다.
   - **요청 조건:** 언어 지정, draft 여부, 관련 이슈, push 허용 범위와 기존 승인. 지정되지 않은 조건을 만들어내지 않는다.
   - **검증 근거:** 수행한 명령·결과·대상 SHA, 실행하지 못한 검증. 현재 SHA와 다르면 재검증 대상으로 표시한다.
5. 결과를 기다리는 동안 메인 에이전트는 같은 브랜치의 코드·커밋·HEAD를 변경하거나 별도 PR을 만들지 않는다.

## 생성 절차 — 전담 서브 에이전트

필요한 조회·PR 생성을 지원하는 연결된 GitHub 도구가 있으면 우선 사용하고, 지원이 부족하면 GitHub CLI를 사용한다. 어느 도구를 사용하든 아래 대상 확인·언어 선택·중복 방지·결과 검증을 동일하게 적용한다.

### 1. 대상과 차이 확인

- 인계된 저장소에서 지침, Git 상태, HEAD, GitHub 인증, base/head 원격을 다시 확인한다. 이 시점의 변경·충돌·승인 불일치는 메인 에이전트에게 반환한다.
- 필요한 원격 ref를 fetch하고 **base...head diff와 base..head 커밋 목록**을 읽어 PR의 최종 변경을 파악한다. 현재 작업 트리의 diff만으로 본문을 쓰지 않는다.
- base와 head가 같거나 비교할 커밋·변경이 없으면 생성하지 않고 이유를 반환한다. PR을 만들기 위해 base를 임의로 바꾸거나 빈 커밋을 만들지 않는다.
- 같은 대상 저장소·base·head 저장소·head 브랜치의 열린 PR을 조회한다. 이미 있으면 URL을 읽기 전용으로 재조회해 대상, head SHA, draft 상태를 확인하고 반환한다. 인계된 SHA와 다르면 해당 차이도 보고한다. 새 PR을 만들거나 기존 본문을 덮어쓰지 않는다.
- `gh pr list --head`에는 브랜치 이름만 사용한다. fork 구별은 반환된 `headRepositoryOwner`, `headRepository`, `baseRefName`으로 확인한다. `<owner>:<branch>`는 이 조회 옵션에서 지원되지 않는다.

### 2. 언어와 템플릿 선택

**대화가 한국어라는 이유만으로 한국어 PR을 작성하지 않는다.** 다음 순서로 선택 근거를 기록하고 **선택한 언어의 reference만 읽는다.**

1. 사용자가 PR 언어를 지정했다면 그 언어를 따른다.
2. 대상 **base 저장소**의 `CONTRIBUTING` 또는 PR 템플릿에 언어 규정이 있으면 따른다.
3. 규정이 없으면 주 README·기여 문서와 최근 병합 PR의 언어를 확인한다. 국제·해외 오픈소스의 기여 언어가 영어이면 **영문**, 한국어 중심 프로젝트이면 **한국어**를 사용한다. 사용자명·국적·코드 식별자만으로 분류하지 않는다.
4. 근거가 없거나 우열 없는 혼합이면 **영문을 기본값**으로 선택하고 그 이유를 결과에 남긴다.

- **영문:** [references/pr-template.en.md](references/pr-template.en.md)
- **한국어:** [references/pr-template.ko.md](references/pr-template.ko.md)

대상 저장소에 PR 템플릿이 있으면 그 구조와 필수 항목을 우선 보존하고, 선택한 reference의 작성 원칙을 적용한다. 언어 지정으로도 저장소의 필수 양식은 생략하지 않는다. 제목과 본문은 선택한 언어로 작성하되 명령·코드 식별자·고정 양식 제목은 원문을 유지할 수 있다.

### 3. 본문과 게시 준비

- 제목은 저장소 컨벤션을 따른다. 본문은 **해결한 문제와 최종 동작**으로 시작하고 diff에서 확인한 변경과 검증 결과만 쓴다. 대화 기록과 폐기한 접근을 나열하지 않는다.
- 선택한 템플릿을 채우고 안내 주석과 불필요한 선택 섹션을 제거한다. 검증을 실행하지 않았거나 실패했다면 그 사실과 이유를 명시한다. 수행하지 않은 테스트를 통과했다고 쓰지 않는다.
- 이슈 자동 종료 구문, 리뷰어·담당자·레이블 지정은 사용자 요청 또는 대상 저장소의 명시된 규칙이 있을 때만 사용한다.
- 본문은 저장소 밖의 UTF-8 임시 파일로 작성한다. 셸 문자열에 본문을 이어 붙이지 않는다. PR에는 `.env`·비밀값·토큰을 포함하지 않는다.
- PR 생성 요청은 확인된 대상에 PR을 만드는 권한으로 취급한다. 이미 승인된 작업에 반복 승인을 요구하지 않는다. 별도 사용자 승인·커밋 규칙이 있으면 인계받은 승인 범위 안에서만 진행한다.
- head가 원격에 없거나 뒤처졌다면 해당 **작업 브랜치만 일반 push**한다. 기본 브랜치 직접 push, force push, 이력 재작성, merge는 이 스킬의 권한에 포함하지 않는다. 새 fork나 추가 권한이 필요해 요청 범위 안에서 해결할 수 없으면 이유를 반환한다.
- push한 원격 head SHA가 인계된 SHA와 같은지 확인한다. 다르면 PR을 만들지 않고 변경 원인을 반환한다.

### 4. 생성과 재확인

- 생성 직전에 동일 base/head의 열린 PR을 다시 조회해 중복을 방지한다.
- GitHub CLI 사용 시 `gh pr create`에 **`--repo`, `--base`, `--head`, `--title`, `--body-file`을 모두 명시**한다. fork의 head는 지원되는 `<사용자>:<브랜치>` 형식으로 지정한다. 사용자 요청이 draft이면 `--draft`를 추가한다.
- `--fill`이나 브라우저 폼 위임으로 선택한 본문을 대체하지 않는다. `--dry-run`도 push할 수 있으므로 읽기 전용 검증으로 사용하지 않는다.
- **생성 요청은 1회 수행한다.** 오류·시간 초과 시 동일 base/head PR을 재조회해 실제 생성 여부부터 확인한다. 존재하면 그 결과를 반환하고, 없거나 확인할 수 없으면 오류와 복구 정보를 반환한다. 확인 없이 반복 생성하지 않는다.
- 성공 시 URL로 PR을 재조회해 대상 저장소, base, head 저장소·브랜치·SHA, 제목, 본문, draft 상태를 검증한다. API 결과를 확인하기 전 완료라고 보고하지 않는다.

## 반환 계약

서브 에이전트는 메인 에이전트에게 다음을 반환한다.

- 상태: **생성됨 / 기존 PR / 차이 없음 / 진행 불가**.
- PR URL 또는 진행 불가 원인과 필요한 조치.
- 대상 저장소, base/head 저장소·브랜치, head SHA, draft 여부.
- 선택한 언어·템플릿과 판단 근거, 검증 결과·미실행 항목. 기존 PR 반환처럼 본문 작성을 생략한 경우 언어·템플릿은 **해당 없음 — 작성 생략**으로 표시한다.
- 이번 실행에서 수행한 push 등 원격 변경. 임시 본문 파일은 생성 절차 종료 후 정리한다.

메인 에이전트는 반환 URL을 읽기 전용으로 확인하고 사용자에게 링크와 핵심 결과를 보고한다. 생성·인증·보호 규칙 오류는 우회하지 않고 구체적으로 설명한다.
